Every layer is doing its job, and one of them is doing it despite a bug

The project's claim is exactly right: 5, 6, 1, 1 swaps and 4, 3 stakes, matching a full-window log scan wallet for wallet. Boney's independent ceiling reads 10, 12, 1, 2 on the swap KPI — roughly double for three referrals, traced below to two relay passes that overlapped and folded the same logs twice.

Nothing over-paid. Credit is min(claim, ceiling) and an adapter may discount but never inflate, so an inflated ceiling simply stopped binding. The asymmetry that exists for the dishonest-project case absorbed an honest-relayer bug instead — the failure surfaced as a number that looks wrong on a dashboard rather than as tokens leaving escrow.

The anomaly, traced

Two relay passes, one block range, counted twice

The ceiling is written additively — stored total plus this pass's delta — so a range folded twice is counted twice. The relayer resumes at checkpoint + 1 for exactly that reason, and that guarantee only holds while one pass runs at a time. Here two overlapped: the second read the checkpoint before the first's transaction landed, scanned from the stale cursor, then read the total after it landed and added its whole delta on top.

Two more things worth knowing

KPI 2 has never matched anything, and may not be able to

A full-window scan with all six referrals OR'd into the actor slot found no referral there at all — not a low count, an empty set. On this event that slot carries the position tokenId, not a wallet, so the address comparison can't succeed; the source catalogue already flags the probe that blessed it as a false positive, because the sampled token id happened to have zero high bytes. The campaign guide has no row for this KPI either, so nothing in the UI invites a promoter to try it. Worth confirming before anyone counts on that 400 GYND ladder.

Separately: the deployed subgraph (v0.5.0) predates the filtered params layout and returns source: null for all three of these KPIs, so it cannot decode this campaign's event sources. Promoters, touches and scores all came back matching the chain exactly — the gap is only in the KPI source fields.
